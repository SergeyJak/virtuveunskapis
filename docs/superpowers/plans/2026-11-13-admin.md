# Admin gallery and visitor analytics Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** Manage portfolio photos and inspect visitors through a protected /admin interface.
**Architecture:** Existing Next.js server, server-only persistence modules, signed cookie sessions. Source projects remain an immutable baseline with persisted overrides; uploads live outside public and are served by a validated media route. Single Node process with a persistent volume; no new dependencies.
**Tech Stack:** Next.js, TypeScript, React, Node crypto/fs, built-in node:test.
**Spec:** docs/admin-architecture.md (user authorized implementation and removed five-file limit).

## Global Constraints
- Preserve existing category slugs, project URLs, localization and public design.
- No secrets in client bundles, no public access to visitor data.
- No new dependencies. Production persistence requires ADMIN_DATA_DIR on a durable volume.
- Do not deploy or alter inventory-app.

## Review Focus
- Concurrent saves must not overwrite unrelated project updates.
- Corrupt persistence must fail visibly rather than silently reset.
- Missing credentials must never allow login or mutations.
- Untrusted paths, origins, and upload bodies must be bounded and rejected.
- New projects and hidden projects must agree across public pages and sitemap.
