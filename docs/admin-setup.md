# Админка проектов и посетителей

Откройте `/admin`. Админка встроена в существующий Next.js; отдельный сервис не нужен. Новых зависимостей нет. Действующие категории и адреса проектов сохранены.

## Локальный запуск

1. `npm ci`.
2. `npm run admin:password` в интерактивном терминале. Введите пароль из 12–256 символов; ввод скрыт. Команда выдаст хеш и случайный секрет сессии. Сам пароль не записывается в исходники.
3. Скопируйте `.env.example` в `.env.local`. Поместите выданные `ADMIN_PASSWORD_HASH` и `ADMIN_SESSION_SECRET` в этот файл. Не публикуйте их.
4. `npm run dev`, затем `/admin`. Сессия действует 8 часов. Смена хеша или секрета завершает все прежние сессии.

Без настроенных значений вход закрыт. Для разработки каталог данных по умолчанию — `.runtime/`, он исключён из Git.

## Сервер

- Используйте Node.js 20.9+ и один экземпляр Node-сервера. `npm ci`, `npm test`, `npm run build`, `npm start`.
- Настройте пароль и секрет через переменные окружения хостинга.
- Обязательно задайте `ADMIN_DATA_DIR` абсолютным путём к подключённому постоянному диску, например `/data/portfolio`. Процесс должен иметь право записи. При отсутствии этой настройки в production сохранение и сбор аналитики возвращают ошибку 503; исходное портфолио продолжает отображаться.
- Диск должен сохраняться после перезапуска и нового деплоя. `public/`, `.next/` и исходники не используются для новых загрузок.
- На Railway подключите volume и задайте `ADMIN_DATA_DIR` его mount path. Включите только одну реплику. Эфемерная или serverless файловая система без постоянного диска не подходит.
- За reverse proxy задайте `SITE_ORIGIN` точным публичным origin, например `https://virtuveunskapis.lv` (без завершающего `/`). Для нескольких доменов админку используйте на одном каноническом домене.
- HTTPS обязателен в production: cookie защищена флагами HttpOnly, Secure и SameSite=Strict. Для проверки production-сборки через localhost используйте браузер, поддерживающий secure cookies на localhost, или локальный HTTPS.
- Не включайте `TRUST_PROXY_HEADERS=true`, пока не проверено, что proxy перезаписывает IP-заголовки и сервер недоступен напрямую. Без этого IP отображается как неопределённый, а ограничение частоты запросов общее для посетителей.

Эта реализация использует сериализацию и атомарную замену JSON внутри одного процесса. Для нескольких реплик нужны общая база данных и объектное хранилище. Не запускайте несколько процессов с одним каталогом.

## Проекты и фотографии

В разделе «Проекты» можно создать проект, выбрать кухню/шкаф/ванную, изменить название и описание, загрузить фотографии, поменять их порядок и выбрать обложку (первая фотография). Поле порядка управляет положением проекта; меньшее число выводится выше. Снимите «Опубликовать», чтобы скрыть проект или сохранить черновик. Скрытие убирает страницу и запись из sitemap, но не делает исходные фотографии конфиденциальными: их URL и исходные данные могут оставаться в ранее загруженных ресурсах сайта.

Загрузка: JPEG/PNG/WebP, до 8 МБ на файл, до 10 файлов и 32 МБ на запрос, до 40 фотографий в проекте. SVG не принимается. Имя файла генерирует сервер. Несохранённые загрузки и фотографии, убранные из проекта, остаются на диске: это позволяет безопасно отменить редактирование и избежать удаления используемых файлов. Следите за свободным местом; автоматического удаления исходников нет.

Исходный каталог остаётся в `data/generated-projects.json` и по-прежнему формируется из исходных фотографий при сборке. Админка сохраняет новые проекты и переопределения отдельно в `projects.json`. Следующая сборка их не стирает. Название и описание, введённые администратором, показываются одинаково на всех языках; автоматический перевод пользовательского текста не выполняется.

## Посетители

Собираются анонимный ID браузера, сессия (новая после 30 минут бездействия), время, просмотры страниц и проектов, выбор категории, клики по контактам, источник и UTM, язык, тип устройства и браузер. ID браузера обновляется через 90 дней. Это оценка по браузерам: другой браузер или очищенное хранилище создают нового посетителя. При отключённом browser storage сайт работает, статистика этого браузера не собирается.

Сессии вошедшего администратора и `/admin` не учитываются. Данные доступны только после входа. Боты по User-Agent скрыты по умолчанию. В разделе посетителей доступны периоды, даты, поиск, сортировка, пагинация и история. Первый визит, источник и повторные посещения рассчитываются внутри выбранного периода. Даты фильтра задаются в UTC, время показывается в часовом поясе браузера.

`ANALYTICS_RETENTION_DAYS` — 1–365, по умолчанию 90. При записи сохраняется максимум 50 000 событий; старые события удаляются при следующей записи и исключаются из чтения сразу по сроку. История показывает последние 1000 событий посетителя. `ANALYTICS_ENABLED=false` останавливает новые записи. Сырые тексты поиска, произвольные query-параметры и полный внешний referrer не сохраняются. География без отдельного доверенного GeoIP-источника не определяется.

## Резервная копия и проверки

Резервируйте весь `ADMIN_DATA_DIR`: `projects.json`, `analytics.json`, `uploads/`. Для согласованной копии остановите сервер либо используйте snapshot диска. После восстановления проверьте `/admin`, обложки и страницы проектов. Повреждённый JSON вызывает ошибку и не сбрасывается в пустой каталог.

Проверки: `npm test`, `npx tsc --noEmit`, `npm run build`. Затем вход, загрузка/публикация/скрытие проекта, отображение на главной/в портфолио/по ссылке, визит из другого браузера и история в админке. После перезапуска сервера опубликованные проекты и статистика должны сохраниться.
